## Deviations from the mock (documented)
1. BM/TL hold `evaluations` at **View** only (product decision on record) → evaluation authoring buttons hidden.
2. BM Recruitment page = real vacancy-request flow (create → status → HR decision). The mock's BM-side candidate-match / 2nd-interview loop is HR-side in the real domain.
3. Settings toggles use the real 5 notification categories (`requests, attendance, recruitment, management, announcements`), not the mock's email/push channel labels. Language select is a client-side preference.
4. Sidebar badge counts derive from live endpoint data; no hardcoded numbers.
5. Profile email shows but is not self-editable — the contact endpoint is phone+address only (`UpdateContactRequestDto`).
6. Payroll "Year to month" panels use real aggregates only: YTD = closed sheets' sums; the mock's monthly-leave-quota concept is replaced by the annual leave balance (no monthly-quota field exists in the domain). The rebuilt §8 page derives accrual/month = allowance ÷ 12 and shows used/left from the balance; the mock's "unpaid if you leave" tile, the per-sheet "annual increase" line, and the per-month late/early/sick/annual/absent/salary-advance stat tiles are not derivable from the real sheet API — the Salary & Schedule tiles show the newest closed sheet's Basic/Bonuses/Deductions/Net instead.
7. Schedule cell tint keys off the shift *name* (`Morning`/`Evening` contains-match); other names fall back to the neutral tint instead of inventing colors.
8. Document upload names derive from the picked file (server has no name field); the mock's separate name input is dropped.
9. Notification rows navigate only when their `link` maps to a portal page (unknown mock ids stay inert rather than guessing routes).
10. My Team's "Check Out" column is omitted — `TeamMemberDayDto` carries check-in only, and no real check-out field exists on the team-day row (no fabrication).
11. The mock team desk's two-step "Rejected Pending HR" state does not exist: stage-1 reject lands directly in `Rejected`, and only `Pending` rows are decidable at stage 1 — "Pending HR" rows offer Edit/View only.
12. Team Schedule (rebuilt this round to mock §16): month select + 7/30-day view + Delete Schedule + drag painting + New Template are all **real**. Semantics differ where the domain differs: "Delete Schedule" removes the cycle row and its per-date assignments (the mock only reset cells to Off); "Show 30 days" = the selected month ∩ the cycle range (real cycles are arbitrary date spans, not per-month periods); template CRUD is the real `ShiftManagementController` surface (`/api/gyms/{id}/shift-templates`) — the mock's per-template color picker and "Off Day" checkbox are not in the contract (colors are server-derived; the seeded Off template covers off-days; overnight shifts (`end ≤ start`) are rejected by the server).
13. Team Performance's quarter select is omitted — real evaluation rows already carry a derived period label shown per row; no period-filter endpoint exists.
14. The member drill-in for Team Leaders lacks the Personal/Contact/Employment sections (they live behind the `employees.view` key, which seeded TLs do not hold); TLs get the viewer-known header via location.state and see Today/Upcoming/Requests/Evaluations. The BM-side profile (Phase 3) fills those sections.
15. Desk Edit modal patches exactly the real contract (type/requestDate/endDate/reason); the mock's amount field is unreachable at stage 1 (amounts ride on the request as submitted).
16. Attendance Management selects a real **date** (native date input, default today) instead of the mock's Today/This Week/This Month select — the composed grid endpoint is date-based. The Present tile counts {On Time, Present, Early Checkout}; Late and Missing Checkout count separately (mock's single 'Present' status does not exist in the real status vocabulary).
17. Employees Performance aggregates come from the gym-scoped lists (request inbox, deductions/warnings/bonuses, evaluation responses, leaving cases) — one fetch each. "Need review" marks employees with an **open leaving case** (the mock's follow-up expense join has no real equivalent for BM). Evaluations join on employee display name (the evaluation-response row carries no employeeId); month filter = real activity months on record.
18. Recruitment tabs are the three real statuses (All/Pending/Approved/Rejected); Decide/Reopen render only for `recruitment.vacancy_request.approve` key holders (no seeded manager holds it). The mock's 5-stage pipeline (match/2nd interview) is HR-side (see 2).

Dashboard "Upcoming Schedule" → **7-Day Schedule**: the strip is 7 consecutive tiles (2 recent past days + today + 4 upcoming) so the per-day check-in/check-out clock times (new `ScheduleDayDto` fields) have visible data on recent days; the mock's strip had no clock times at all (user-requested addition). Every date gets a tile — dates without an assignment row render as OFF.
