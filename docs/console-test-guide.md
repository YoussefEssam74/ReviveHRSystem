## Behaviors worth exercising

1. **Gym scoping** — log in as `hr@` (gym1 only) vs `hrmanager@` (both): every list changes size accordingly; no cross-gym leakage.
2. **403 handling** — open a module the role lacks (e.g. `karim@` → `/console/payroll`): an inline "no access" message, never a crash.
3. **Branch → HR round trip** — as `omar@` raise a warning/bonus proposal, then as `hr@` review it in Branch Queue; approving a deduction lands it in the October payroll entry totals.
4. **Events derive themselves** — the Events queue is generated by `EventsService` from live data (contracts, payroll, offboarding, requests) and prunes stale cards. Do **not** seed events manually; rows get rewritten or removed on the next derivation.
5. **Payroll lifecycle** — October is Draft with pending lines (from attendance + accepted deductions); Jul–Sep are Locked+Paid history.
6. **Evaluation detail** — open a submitted response: rating answers render as `{"score":N}` JSONB, choice answers as `{"selectedValues":[...]}`.

## Resetting / re-running

The seeder is resumable and marker-guarded: restarting the API re-checks specific seed markers (never bare `AnyAsync`), so your own manual data never causes silent skips and nothing is wiped. To force a full rebuild of the dataset, drop the `ReviveHrSystemDb` database and restart the API in Development.
